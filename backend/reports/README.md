# 검증 보고서

조합 탐색(`backend/sweeps/`) 결과로 추천 조합과 그 근거를 정리한 문서다. 대시보드의 검증 리포트 탭이 읽는다.

## 폴더 구조

```
reports/<전략 id>/<보고서 이름>/
├─ report.md    추천 조합과 근거. 탐색이 쌓일 때마다 같은 파일을 갱신한다
└─ table.csv    비교표. `python -m app.sweep table <전략 id> --name <보고서 이름>`이 만든다
```

- 보고서 이름은 짧은 한글 또는 소문자 영문과 하이픈이다. 예: `익절손절-민감도`
- 보고서를 갱신하면 같은 `report.md`를 덮어쓰고, 이전 내용은 Git 이력에 남는다.
- 한 전략에 보고서가 여러 개일 수 있다. 서로 다른 질문(예: 익절·손절 기준, 이동평균 길이)마다 하나씩 쓴다.

## report.md 형식

파일은 JSON 머리말로 시작한다. 머리말은 `---` 줄 두 개 사이의 JSON 객체 하나다.

```
---
{ ...머리말... }
---

# 보고서 제목
...
```

### 머리말 필드

| 필드 | 내용 |
| --- | --- |
| `strategy_id` | 전략 id |
| `name` | 보고서 이름. 폴더 이름과 같다 |
| `title` | 화면에 보일 제목 |
| `question` | 이 보고서가 답하려는 질문 한 문장 |
| `updated` | 마지막 갱신일 `YYYY-MM-DD` |
| `author` | 작성한 도구와 모델. 예: `Codex (gpt-5)` |
| `result_count` | 보고서가 근거로 쓴 `results.jsonl` 줄 수 |
| `periods` | 비교한 기간 목록. 각 항목은 `{label, start, end, kind}`이고 `kind`는 `full`(전체) 또는 `split`(구간) |
| `recommended` | 추천·대안 조합 목록. 각 항목은 `{id, role, label}`이고 `role`은 `recommended` 또는 `alternative`다. `id`는 `results.jsonl`의 `id`다 |

### 본문 섹션

아래 제목과 순서를 지킨다. 해당 내용이 없으면 "없음"이라고 쓴다.

| 섹션 | 내용 |
| --- | --- |
| `## 요약` | 결론 두세 문장과 신뢰 수준(높음·보통·낮음)과 그 이유 |
| `## 탐색 범위` | 바꾼 파라미터와 값, 고정한 파라미터, 비교한 기간, 슬리피지·수수료율, 초기자금, 시도 횟수 |
| `## 추천 조합` | 추천·대안 조합의 파라미터와 기간별 핵심 지표 표 |
| `## 근거` | 아래 판단 기준별로 표나 문장으로 정리한다 |
| `## 위험과 한계` | 표본 크기, 데이터 기간, 다시 확인할 점 |
| `## 다음 탐색 제안` | 다음에 돌릴 조합과 이유, 요청 블록 |
| `## 변경 이력` | 갱신할 때마다 한 줄: `날짜 — 무엇이 바뀌었나 (시도 N건)` |

### 다음 탐색 요청 블록

`## 다음 탐색 제안`에는 `sweep-request`로 표시한 코드 블록 하나를 둔다. 내용은 `python -m app.sweep run`의 요청 파일과 같은 JSON이다. 대시보드는 이 블록을 복사하기 쉽게 보여 준다.

````
```sweep-request
{ "strategy_id": "...", "initial_capital": 100000, "periods": [...], "params": [...], "grid": {...} }
```
````

## 추천 근거의 판단 기준

최고 순손익 하나를 고르지 않는다. 조건 변화에 흔들리지 않는 조합을 추천한다.

| 기준 | 확인 방법 |
| --- | --- |
| 기간별 일관성 | 구간(`split`)마다 순손익 부호와 크기가 비슷한가. 한 구간이 전체 이익의 대부분이면 낮게 본다 |
| 이웃 조합 안정성 | 파라미터를 한 칸 바꾼 조합도 비슷하게 좋은가. 뾰족한 한 점이면 우연으로 본다 |
| 비용 영향 | `fee_ratio`가 큰가(수수료가 총손익을 얼마나 깎는가). 총손익이 0 이하면 비용 이전에 손실이다 |
| 위험 | `max_drawdown_rate`와 `sharpe`. 이익이 같으면 낙폭이 작은 쪽을 고른다 |
| 표본 | `trade_count`가 30건 미만이면 "표본 적음"을 적는다 |
| 시도 횟수 | 많이 시도할수록 우연히 좋은 조합이 나온다. 시도 횟수를 항상 적는다 |

## 수치 규칙

- 본문의 모든 수치는 `table.csv`나 `results.jsonl`의 값이다. 눈대중이나 암산으로 만들지 않는다.
- 표에 없는 통계가 필요하면 `results.jsonl`과 거래 파일을 읽는 코드로 계산하고, 어떤 값을 어떻게 계산했는지 쓴다.
- 조합을 말할 때는 파라미터 값과 `id` 앞 8자를 함께 쓴다.
- 비율은 퍼센트로, 금액은 천 단위 쉼표로 쓴다. 단위(계약, 원, 달러)는 전략 문서를 따른다.
