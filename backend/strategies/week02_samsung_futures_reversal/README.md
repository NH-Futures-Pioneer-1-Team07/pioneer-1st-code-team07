# 삼성전자선물 고저점 역매매 전략

- 판단 규칙: [week02_samsung_futures_reversal.md](../../../docs/strategies/week02_samsung_futures_reversal.md)
- 구현: [strategy.py](strategy.py)
- 파라미터: [manifest.json](manifest.json). 이름과 기본값은 전략 문서 10절과 같다.

## 호출 방식

- `on_bar`: 3분봉이 마감될 때마다 호출한다. 후보 봉 확인, 진입, 목표 갱신, 시각 규칙을 처리한다.
- `on_price`: 장중 가격이 갱신될 때 `ctx.price`를 채워 호출한다. 진입분별 손절·이익 청산과 시각 규칙을 처리한다.
- 같은 봉에는 `on_bar`를 한 번만 호출해야 한다.
- 손절·목표 청산은 `on_price`에서만 판단한다. 호출하는 쪽이 `on_price`를 호출하지 않으면 청산하지 않는다. 봉 단위로 실행하는 백테스트는 봉 안의 가격(고가·저가)으로 `on_price`를 호출해야 한다.
- 시작·재시작 전 봉으로 주문하지 않으려면, 호출하는 쪽이 시작 이후 완성된 봉만 `bars`에 넣어야 한다.

## 구현 해석

전략 문서에 없는 부분을 다음과 같이 정했다.

| 항목 | 해석 |
| --- | --- |
| 기준 저점·기준 고점 | 후보 봉이 시작되기 전에 확정된 가장 최근 저점·고점이다. 확인 조건도 이 값과 비교한다. |
| 후보와 확인 | 후보 봉이 나오면 상태 `candidate`에 저장하고, 바로 다음 `on_bar`에서 확인한다. 다음 봉이 연속한 봉이 아니면 후보를 버린다. |
| 거래량 조건 | 확인 봉 거래량이 평균 거래량 × `volume_min_ratio` 이상이면 진입한다(같으면 진입). 평균은 확인 봉을 뺀 당일 직전 `volume_avg_bars`개 봉이다. |
| 진입 수량 | 거래량과 관계없이 `entry_quantity`로 고정한다. |
| 진입분 id | `<날짜>-<번호>`로 진입 주문마다 새로 만든다. 체결된 보유분(`Lot`)은 같은 id로 전달돼야 한다. |
| 진입분 상태 | 진입 주문을 낼 때 `positions`에 손절 기준, 이익 청산 목표를 기록한다. 보유도 미체결도 없고 주문 유효 시한(`order_valid_bars`)을 넘긴 진입분은 지운다. 상태를 잃으면 그 진입분은 관리하지 못한다. |
| 손절 기준 | 매수는 기준 저점 − `stop_offset`, 매도는 기준 고점 + `stop_offset`이다. |
| 첫 이익 청산 목표 | 후보 봉이 시작되기 전에 확정된 가장 최근 반대쪽 고점(매수)·저점(매도)이다. |
| 도달 | 매수는 가격이 목표 이상이면 목표 도달, 손절 기준 이하이면 손절이다. 매도는 반대로 목표 이하, 손절 기준 이상이다. |
| 목표 갱신 | `target_mode`가 `갱신`이면, 진입 확인 봉이 마감된 뒤 새로 확정된 반대쪽 고점·저점 중 가장 최근 값으로 목표를 바꾼다. 진입 전에 이미 확정된 값은 새 값이 아니다. |
| 갱신 시점 즉시 청산 | 목표를 바꾼 `on_bar`에서 `ctx.price`(없으면 마지막 봉 종가)가 새 목표에 도달했으면 바로 청산한다. 같은 호출에서 손절 기준에도 닿았으면 이유를 손절로 한다. |
| 목표 고정 | `target_mode`가 `고정`이면 첫 목표를 바꾸지 않는다. 손절과 청산 규칙은 같다. |
| 청산 반복 | 청산 주문이 나간 진입분에는 다시 주문하지 않는다. 일부만 체결돼 보유분이 남고 청산 주문이 없으면 다음 `on_price`에서 남은 수량을 다시 청산한다. |
| 미체결 주문 | `open_orders`가 비어 있지 않으면(청산 주문 포함) 새 진입 신호를 건너뛴다. 상태가 불확실한 주문도 `open_orders`에 포함해 전달해야 한다. |
| 보유 중 신호 | 같은 방향이면 추가 진입하고, 반대 방향이면 건너뛴다. |
| 신규 진입 제한 시각 | 처음 호출될 때 `open_orders`를 모두 취소하고, 취소한 청산 주문의 남은 수량을 청산 주문으로 다시 낸다. 진행 중인 후보는 버린다. 호출하는 쪽은 취소를 먼저 처리한 뒤 주문을 전송해야 한다. |
| 당일 청산 시각 | 처음 호출될 때 `open_orders`를 모두 취소하고 모든 보유분의 청산 주문을 낸다. 같은 날 다시 청산하지 않는다. 청산 상태 확인과 재시도는 이 전략이 하지 않는다. |
| 최종거래일 | `last_trading_day`가 오늘이면 신규·추가 진입을 하지 않고, 보유분이 있으면 처음 호출될 때 청산 주문을 낸다. `last_trading_day`가 `None`이면 신규·추가 진입을 하지 않는다. |
| 판단 기록 | 호출마다 결과를 남긴다. 진입은 매수·매도, 후보 발생·확인 실패·후보 없음은 보류, 신호를 건너뛰면 건너뜀과 이유를 남긴다. 손절·목표 청산도 판단으로 남긴다. 점수는 쓰지 않는다. |

## 상태

`ctx.state`와 `StrategyOutput.state`로 다음을 주고받는다. 날짜가 바뀌면 초기화한다.

- `day`: 상태가 속한 날짜
- `entry_count`: 오늘 낸 진입 주문 수
- `candidate`: 확인을 기다리는 후보 봉(방향, 시각, 기준값, 반대쪽 목표)
- `positions`: 진입분별 방향, 손절 기준, 이익 청산 목표, 목표 출처 봉 위치, 진입 확인 봉 위치, 정보 만료 시각
- `cutoff_done`, `flatten_done`, `final_exit_done`: 시각·날짜 규칙을 오늘 이미 처리했는지
