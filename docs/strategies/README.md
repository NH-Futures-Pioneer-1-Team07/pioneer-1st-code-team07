# 전략 문서 작성 가이드

## 목적

- 전략 문서는 구현 담당자가 이 문서만 읽고 전략 코드를 만들 수 있게 쓴다.
- 전략 문서에는 전략의 판단만 쓴다.
- 주문 전송·계좌 확인·기록 같은 운영 방식은 전략 문서에 쓰지 않는다.

## 위치와 이름

- 전략 문서는 `docs/strategies/` 바로 아래에 둔다.
- 파일 이름은 전략 ID(`backend/strategies/` 폴더 이름)와 같게 쓴다. 예: `week02_samsung_futures_intraday.md`
- 전략 하나에 문서 하나를 쓴다.

## 쓸지 말지 판단하는 기준

- 이 규칙이 다른 전략에서도 똑같이 적용되는가?
  - 그렇다: 쓰지 않는다. 플랫폼이 처리한다.
  - 아니다: 다음 질문으로 간다.
- 이 규칙이 매수·매도 여부, 수량, 가격 기준, 시각·날짜 중 하나를 정하는가?
  - 그렇다: 쓴다.
  - 아니다: 쓰지 않는다.
- 규칙을 바꾸면 매매 결과가 달라지는가?
  - 그렇다: 쓴다.
  - 아니다: 쓰지 않는다.

## 반드시 쓸 내용

문서에는 아래 절을 이 순서로 쓴다. 해당 없는 절은 "해당 없음"이라고 적는다.

### 1. 범위

- 대상 상품과 매매 방식을 한두 줄로 쓴다.
- 전략이 판단하는 것을 항목으로 나열한다.

### 2. 상품과 입력 자료

- 대상 종목의 이름, 월물, 종목코드, 거래승수를 쓴다.
- 판단에 쓰는 봉 단위와 시간대를 쓴다.
- 판단에 쓰는 자료 항목을 쓴다. 예: 고가, 저가, 종가, 거래량
- 자료 항목마다 의미가 헷갈릴 수 있으면 의미를 쓴다. 예: 거래량이 누적인지 봉 구간 값인지
- 사용하는 봉의 범위를 쓴다. 예: 당일 완성된 봉만, 전일 봉은 쓰지 않음
- 시작·재시작 후 어느 봉부터 판단에 쓰는지 쓴다.

### 3. 지표와 기준값 정의

- 판단에 쓰는 지표와 기준값을 하나씩 정의한다.
- 정의마다 계산에 쓰는 봉의 개수와 범위를 쓴다.
- 판단 대상 봉을 계산에 포함하는지 제외하는지 쓴다.
- 값이 확정되는 시점을 쓴다.

### 4. 신호 조건

- 매수 신호와 매도 신호를 각각 따로 쓴다.
- 신호마다 조건을 항목으로 나누고, 항목은 모두 만족해야 하는지 하나만 만족하면 되는지 쓴다.
- 비교는 연산자를 말로 정확히 쓴다. 예: 초과, 이상, 미만, 이하
- 두 방향 신호가 동시에 나올 때의 처리를 쓴다.
- 같은 신호가 반복될 때의 처리를 쓴다. 예: 매 봉마다 주문하지 않는다.

### 5. 진입 수량

- 수량 계산식을 쓴다.
- 반올림 방식을 쓴다. 예: 소수점 버림
- 계산 결과가 0일 때의 처리를 쓴다.
- 수량의 상한과 하한을 쓴다. 상한이 없으면 "상한 없음"이라고 쓴다.
- 보유 중 같은 방향 신호와 반대 방향 신호의 처리를 각각 쓴다.
- 반대 신호로 포지션을 줄이거나 뒤집는 규칙을 쓴다. 예시 숫자를 함께 쓴다.

### 6. 주문 방식

- 진입과 청산에 쓰는 주문 유형을 쓴다. 예: 시장가
- 주문의 유효 시한이 있으면 쓴다. 예: 신호 다음 3분봉 마감까지
- 유효 시한이 지났을 때 전략이 하는 행동을 쓴다. 예: 남은 수량을 취소하고 다시 주문하지 않는다.

### 7. 청산 규칙

- 이익 청산 목표와 손절 기준을 각각 쓴다.
- 목표와 손절이 동시에 만족될 때 우선하는 쪽을 쓴다.
- 진입이 여러 번일 때 청산 기준을 진입별로 적용하는지 합쳐서 적용하는지 쓴다.
- 반대 신호가 청산에 영향을 주는지 쓴다.
- 손절이나 목표가 없는 전략이면 "없음"이라고 쓴다.

### 8. 시각과 날짜 규칙

- 신규 진입을 제한하는 시각을 쓴다.
- 당일 청산 시각과 청산 방식을 쓴다.
- 최종거래일의 신규 진입과 청산 규칙을 쓴다.
- 시각은 `HH:MM` 형식으로 쓰고 시간대를 한 번 명시한다.

### 9. 신호를 건너뛰는 조건

- 신호가 나와도 주문하지 않는 조건을 항목으로 나열한다. 예: 직전 봉이 10개보다 적음, 평균 거래량 0
- 건너뛴 이유를 남겨야 하면 이유 이름을 쓴다.

### 10. 파라미터

- 값을 바꿔 볼 수 있는 수치를 항목으로 나열한다.
- 항목마다 이름, 기본값, 의미를 한 줄로 쓴다.
- 본문에 나오는 수치는 모두 이 목록에 있는 이름으로 쓴다.

### 11. 미정 항목

- 아직 정하지 않은 값과 규칙을 항목으로 나열한다.
- 미정인 항목을 본문에서 확정된 것처럼 쓰지 않는다.
- 미정 항목마다 임시 기본값이 있으면 함께 쓴다.

### 12. 관련 API 문서

- 판단에 필요한 자료를 얻는 API 문서만 링크한다.

## 쓰지 않을 내용

- 주문 전송, 주문 상태 조회, 부분 체결 처리 방법
- 주문 가능 수량 확인 방법
- 미체결 주문 취소의 실행 방법과 재확인 간격
- 시작·재시작 시 계좌·포지션 대조
- 봉 누락 시 재조회와 복구 방법
- 봉이 완성됐는지 확인하는 방법
- 연결 오류, 응답 없음, 상태 불확실 때의 처리
- 종가 단일가 시간의 주문 처리
- API 호출 제한
- 실행 기록과 로그의 항목·형식
- 백테스트 결과 계산 가정과 성과 표시 방법
- 모의 체결과 시뮬레이션의 구분
- 구현 진행 상황. 예: "아직 구현하지 않았다"
- 수익성 보장이나 다른 전략과의 차별성 주장
- 화면 표시 방법

## 문장 작성 규칙

- 한 항목에는 한 규칙만 쓴다.
- 항목은 `-` 목록으로 쓴다. 문단으로 이어 쓰지 않는다.
- 조건은 "조건이면 행동한다" 형태로 쓴다.
- 모호한 표현을 쓰지 않는다. 예: 적절히, 가능하면, 필요 시, 대체로
- 수치에는 단위를 쓴다. 예: 계약, 원, 틱, 분
- 같은 개념은 같은 낱말로 쓴다.
- 비교·대응 관계가 3개 이상이면 표로 쓴다.
- 예시는 숫자를 넣어 구체적으로 쓴다.
- 이유는 규칙 바로 아래 항목 하나로만 쓴다. 이유가 길면 쓰지 않는다.

## 용어

- 매수, 매도: 포지션 방향
- 진입: 포지션을 새로 열거나 늘리는 것
- 청산: 포지션을 줄이거나 닫는 것
- 진입분: 한 번의 진입으로 생긴 수량
- 신호 봉: 신호를 판단하는 완성된 봉
- 기준 고점·기준 저점: 신호 봉이 시작되기 전에 확정된 고점·저점

## 문장 예시

| 쓰지 않는다 | 쓴다 |
| --- | --- |
| 거래량이 충분하면 진입한다. | 확인 봉 거래량이 직전 10개 봉 평균의 0.5배 이상이면 진입한다. |
| 가능하면 시장가로 주문한다. | 진입 주문은 시장가다. |
| 장 마감 무렵에 포지션을 정리한다. | 15:30에 잔여 포지션 전량을 시장가로 청산한다. |
| 주문이 체결되지 않으면 적절히 처리한다. | 진입 주문이 신호 다음 3분봉 마감까지 미체결이면 남은 수량을 취소하고 다시 주문하지 않는다. |
| 계좌를 확인한 뒤 주문한다. | (쓰지 않는다. 플랫폼이 처리한다.) |

## 작성 후 확인

- [ ] 12개 절이 순서대로 있다.
- [ ] 매수 신호와 매도 신호가 각각 따로 쓰여 있다.
- [ ] 모든 비교에 연산자가 정확히 쓰여 있다.
- [ ] 수량 계산식에 반올림과 0 처리가 있다.
- [ ] 목표와 손절이 동시에 만족될 때의 우선순위가 있다.
- [ ] 시각 규칙에 신규 진입 제한, 당일 청산, 최종거래일이 있다.
- [ ] 본문의 수치가 모두 파라미터 목록에 있다.
- [ ] 미정 항목이 본문에서 확정된 것처럼 쓰여 있지 않다.
- [ ] "쓰지 않을 내용"에 해당하는 서술이 없다.
- [ ] 모호한 표현이 없다.
- [ ] 문서 안의 링크가 모두 실제 파일을 가리킨다.
