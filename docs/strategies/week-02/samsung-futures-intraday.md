# 삼성전자선물 장중 전략 구현 명세

## 목적과 범위

- 삼성전자 개별주식선물 1개 월물의 규칙 기반 장중 매매를 NH선물 모의환경에서 구현한다.
- 고점·저점으로 추세를 판단하고 같은 방향의 돌파에서 거래량에 비례한 수량을 거래한다.
- 삼성전자만의 차별적 가설과 전략의 유효성은 아직 검증되지 않았다. 수익성을 보장하거나 기존 유명 전략과의 차별성을 입증된 사실로 표현하지 않는다.
- 코드와 실제 모의 주문·체결은 아직 구현하거나 검증하지 않았다. 이 문서는 구현 명세이며 과거 가상 체결 결과를 모의계좌 체결로 사용하지 않는다.

## 상품과 시세

- 테스트 대상: 삼성전자선물 2026년 11월물 `A116B000`. 모의 현재가 API에서 거래승수 10과 최종거래일 `20261112`를 확인했다. 실행 시 종목·월물 및 최종거래일을 다시 확인한다.
- 조회 기준: 주간, 완성된 3분봉, 한국 시간. `domestic/chart-minute`의 `dcnt=3`을 사용한다.
- 모의환경의 해당 종목·2026-10-27 데이터에서는 `occurs1_cum_trd_qty`가 당일 누적이 아닌 **해당 봉의 거래량**으로 관찰됐다. 다른 날짜나 환경에 일반화하지 말고 확인한다.
- 프로그램 시작·재시작 후 새로 완성된 당일 봉부터 모은다. 시작 전 봉과 전일 봉은 신호 계산에 사용하지 않는다. 시작 전에 이미 발생한 신호로 주문하지 않는다.
- 시작 시 보유 포지션과 미체결 주문을 조회해 전략 기록과 대조한다. 불일치하거나 확인할 수 없으면 신규 주문을 중단하고 상태 조회와 오류 기록을 계속한다. 이미 접수된 주문은 계속 체결될 수 있다.
- 3분봉을 중복 처리하지 않는다. 봉의 시간 표시, 완성 여부와 API 반영 지연을 실제 모의환경에서 확인한다. 응답에 표시됐다는 이유만으로 완성됐다고 단정하지 않는다.

## 고점·저점과 추세

5개 연속 완성 봉에서 가운데 봉을 후보로 한다. 앞쪽과 뒤쪽 각 2개 봉은 시간 순서상 후보 봉의 전후를 뜻한다.

- **고점:** 가운데 봉 고가가 앞쪽 2개 봉의 각 고가 이상이고 뒤쪽 2개 봉의 각 고가보다 높다.
- **저점:** 가운데 봉 저가가 앞쪽 2개 봉의 각 저가 이하이고 뒤쪽 2개 봉의 각 저가보다 낮다.
- 후보는 뒤쪽 2개 봉이 완성된 뒤에만 확정한다. 미래 봉으로 확인되기 전에는 신호에 사용하지 않는다.
- 각각 가장 최근에 확정된 고점 2개와 저점 2개를 비교한다. 둘 다 높아지면 상승, 둘 다 낮아지면 하락으로 판단한다. 하나라도 같거나 방향이 엇갈리거나 값이 부족하면 판단을 보류한다.

## 돌파와 신호

- 신호 봉이 **시작되기 전에** 확정된 최신 고점 또는 저점을 돌파 기준으로 고정한다. 해당 봉이 마감되면서 새로 확정되는 고저점은 그 봉의 돌파 기준으로 쓰지 않는다.
- 봉 마감 시점까지 확정된 고저점으로 추세를 판단한다. 따라서 추세 확인과 돌파가 같은 봉 마감에서 함께 발생할 수 있다.
- 상승 추세에서 이전 봉 종가가 기준 고점 이하이고 신호 봉 종가가 그 고점보다 높으면 매수 신호다.
- 하락 추세에서 이전 봉 종가가 기준 저점 이상이고 신호 봉 종가가 그 저점보다 낮으면 매도 신호다.
- 추세 확인 전에 이미 일어난 돌파는 소급해 신호로 인정하지 않는다. 가격이 기준 위나 아래에 계속 머문다는 이유만으로 매 봉마다 주문하지 않는다.

## 수량과 장중 주문

```text
평균 거래량 = 신호 봉을 제외한 직전 10개 완성 3분봉 거래량의 평균
신호 수량 = floor(5 × 신호 봉 거래량 / 평균 거래량)
```

- 직전 봉이 10개보다 적거나 평균이 0이면 해당 신호를 건너뛰고 사유를 기록한다. 계산된 수량이 0이어도 주문하지 않는다.
- 각 유효 신호의 수량은 독립적으로 계산한다. 전략 자체의 전체 보유량 한도는 현재 두지 않는다. 다른 거래일을 더 테스트한 뒤 재검토한다.
- 장중 신호 주문은 시장가로 시도한다. 체결 가격·전량 체결은 보장하지 않는다.
- 신규 진입 가능 수량이 계산된 수량보다 적으면 확인된 가능 수량만 주문하고 차이를 기록한다. 청산 가능 수량과 신규 진입 가능 수량을 구분한다. API가 실제로 어떻게 반환하는지 검증해야 한다.
- 이전 주문이 미체결이거나 주문 상태가 불확실하면 새 장중 신호를 건너뛰고 기록한다.
- 신규 진입 주문이 신호 다음 3분봉 마감까지 미체결이면 남은 수량을 취소 요청하고 실제 취소·체결 상태를 확인한다. 취소분을 같은 신호로 다시 주문하지 않는다.
- 장중 신규 주문이 명확히 거부되면 사유를 기록하고 해당 신호를 종료한다. 응답이 없으면 거부로 단정하지 말고 실제 주문 상태를 확인한다.

## 반대 신호와 포지션 전환

- 반대 신호도 거래량 공식으로 계산한 수량만큼 거래한다. 수량이 기존 보유량보다 작으면 일부 청산, 같으면 전량 청산한다.
- 계산 수량이 보유량보다 크면 기존 포지션을 먼저 전량 청산한다. 청산 체결 및 포지션을 확인한 뒤 초과분만 반대 방향에 신규 진입한다.
- 신규 반대 진입은 신호 다음 3분봉이 끝나기 전까지만 허용한다. 기한이 지나면 초과분 신규 진입은 하지 않지만, 원래 요청한 기존 포지션 청산은 계속 관리한다.
- 예: 매수 10계약 보유 상태에서 매도 신호 5계약, 7계약, 5계약이 차례로 모두 체결되면 결과는 매수 5계약 → 매도 2계약 → 매도 7계약이다.
- 별도의 돌파 실패 손절은 현재 확정하지 않았다. 반대 신호가 약하면 기존 포지션이 일부 남을 수 있다.

## 시간과 당일 청산

당일 청산과 시각은 임시 결정이며 추후 변경할 수 있다. 실제 시장·모의환경 시간과 단일가 거래 처리는 구현 전에 검증한다.

- 일반 거래일 15:24부터 신규 진입과 보유 수량 증가는 제한한다. 기존 포지션을 줄이는 반대 거래는 허용하되 초과분으로 새 반대 포지션을 열지 않는다.
- 15:24에 장중 미체결 주문을 모두 취소 요청하고 취소·체결 결과와 실제 보유 수량을 확인한다. 기존 청산 주문이 취소됐고 원래 청산 대상이 남았다면 확인 후 그 잔여 청산을 이어간다. 신규 반대 진입은 하지 않는다.
- 15:30에 미체결 주문을 다시 확인·취소 요청하고, 취소와 실제 보유량을 확인한 뒤 남은 포지션 전량을 시장가로 청산 시도한다. 이 당일 청산은 거래량 조건을 적용하지 않는다.
- 5초 간격으로 주문 상태와 잔여 포지션을 확인한다. 미체결 주문을 취소해야 한다면 취소 완료를 확인하고 실제 잔여 수량만 다시 주문한다. 상태가 불확실하면 중복 주문을 멈추고 조회를 계속한다. 5초마다 무조건 재주문하지 않는다.
- 15:35 이후 종가 단일가 시간도 청산 기회로 활용하려는 방향이다. 모의환경의 주문·취소·체결 지원 여부와 재시도 마감 시각은 아직 미확정이다. 미체결·오류가 남으면 완료로 표시하지 말고 기록한다.
- 최종거래일에는 신규 진입하지 않는다. 최종거래일을 확인하지 못하면 신규 진입을 막고 다시 조회·기록한다. 이미 보유한 포지션과 미체결 주문은 확인 후 거래 가능한 시간에 청산을 시도한다. 최종거래일 처리의 모의 동작은 미검증이다.

## 데이터 누락과 상태 오류

- 예상한 완성 3분봉을 받지 못하면 5초 간격으로 다음 3분봉이 끝나기 전까지 재조회한다. 끝내 확인하지 못하면 해당 봉의 신호는 처리하지 않고 오류를 기록한다.
- 봉 누락을 복구하지 못했을 때 봉·고저점 계산 상태를 초기화하고 누락 이후 확인된 완성 봉부터 다시 모은다. 필요 데이터가 쌓일 때까지 새 신호 주문을 중지한다. 기존 포지션·주문·체결 기록은 유지한다.
- 주문 접수, 취소 또는 계좌 상태가 불확실하면 신규 주문을 중단하고 상태를 재조회한다. 확인되지 않은 취소를 완료로 간주하지 않는다. 실제 보유 수량이 확인된 경우 기존 청산과 시간 제한은 계속 처리한다.
- 각 요청은 API 유형별 호출 제한을 준수한다. 문서의 LV1 기준은 주문 5건/초, 계좌 조회 10건/초, 시세 조회 10건/초다. 동시에 발생하는 요청까지 함께 관리한다.

## 기록과 검증

- 날짜별 파일 하나에 신호와 건너뛴 사유, 주문 요청·거부·취소, 실제 체결 가격과 수량, 포지션, 오류, 청산 결과를 시간순으로 기록한다.
- 전략 손익은 실제 체결을 근거로 계산한다. 계좌 확정손익·수수료와 비교하고 차이와 계좌 내 다른 거래의 영향을 확인한다. 인증정보·토큰은 기록하지 않는다.
- 프로그램 내부 시뮬레이션과 모의계좌의 실제 주문·체결을 명확히 구분한다.
- 주문 가능 수량·부분 체결·취소 확인, 시작 시 계좌 대조, 3분봉 확정 여부, 최종거래일 및 종가 단일가 청산을 모의환경에서 검증한다.
- 가정상 다음 봉 시가 체결 결과는 실제 체결이나 전략의 수익성을 입증하지 않는다. 거래량 비례 수량, 거래 빈도, 보유 수량과 장중 손실은 더 많은 거래일과 비용을 포함해 검증한다.
