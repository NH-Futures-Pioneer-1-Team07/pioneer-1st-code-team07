# 삼성전자선물 고저점 역매매 전략

## 기본 설정

삼성전자선물을 대상으로 완성된 3분봉으로 진입 신호를 판단한다.
고점·저점과 거래량 평균에는 당일 봉만 사용하며 전날 자료를 이어 쓰지 않는다.

## 분봉 조회와 시작·재시작

직접 조회한 3분봉을 사용하고 이미 처리한 봉은 다시 판단하지 않는다.
예상한 완성 봉이 확인되지 않으면 5초 간격으로 다음 3분봉이 끝나기 전까지 다시 조회한다.
끝내 확인되지 않으면 해당 봉을 신호 처리하지 않고 오류를 기록한다.
신호 계산용 봉과 고저점 상태를 초기화하고 이후 확인된 봉부터 다시 모은다.
거래량과 고저점 판단에 필요한 봉이 쌓이기 전까지 신규·추가 진입을 멈춘다.
기존 주문, 포지션, 체결 기록은 유지하고 포지션 관리와 당일 청산을 계속한다.
봉이 없는 이유는 무체결 또는 API·원천 자료 문제 중 무엇인지 아직 확인되지 않았다.
봉 공백 처리 규칙은 그 원인을 확인하기 전까지 유지한다.
응답에 봉이 존재한다는 사실만으로 완성됐다고 단정하지 않는다.
봉 완성 직후의 반영 지연과 미완성 봉 구분 방법은 모의환경에서 검증한다.

시작·재시작 시 실제 보유 수량과 미체결 주문을 전략 기록과 대조한다.
일치하면 기존 포지션 관리를 이어간다.
불일치하거나 상태를 확인할 수 없으면 신규 주문을 멈추고 오류를 기록하며 상태 조회를 계속한다.
이미 접수된 주문은 자동으로 멈추지 않으므로 실제 체결·취소 여부를 확인한다.
기존 포지션과 미체결 주문을 임의로 완료 처리하지 않는다.
이전 분봉은 불러와 신호에 사용하지 않고 시작 후 새로 완성된 당일 3분봉부터 모은다.
필요한 자료가 쌓이기 전에도 기존 포지션의 청산과 시간 제한을 우선 적용한다.

## 고점·저점 확정

가운데 봉의 고가가 앞 2개 봉의 고가 이상이고 뒤 2개 봉의 고가보다 모두 높으면 고점이다.
가운데 봉의 저가가 앞 2개 봉의 저가 이하이고 뒤 2개 봉의 저가보다 모두 낮으면 저점이다.
뒤따르는 2개 봉이 완성된 뒤에 해당 고점 또는 저점을 확정한다.
신호 봉이 시작되기 전에 확정된 고점·저점만 그 봉의 기준으로 사용한다.

## 진입

| 방향 | 후보 봉 | 다음 완성 봉의 확인 |
| --- | --- | --- |
| 매수 | 저가가 최근 확정 저점 이하이고 종가가 그 저점보다 높다 | 종가가 후보 저점보다 높다 |
| 매도 | 고가가 최근 확정 고점 이상이고 종가가 그 고점보다 낮다 | 종가가 후보 고점보다 낮다 |

같은 봉에서 매수 후보와 매도 후보가 동시에 발생하면 어느 방향도 확인하지 않고 해당 봉을 건너뛴다.
매수 후보 봉이 시작되기 전에 확정된 반대쪽 고점이 없으면 해당 매수 신호를 건너뛴다.
매도 후보 봉이 시작되기 전에 확정된 반대쪽 저점이 없으면 해당 매도 신호를 건너뛴다.
확인 봉의 거래량이 그 봉을 제외한 직전 완성 3분봉 10개 평균의 0.5배 이상일 때만 신규·추가 진입한다.
분봉 API의 `occurs1_cum_trd_qty`는 확인된 모의 환경의 해당 종목·날짜에서 봉 구간 거래량으로 사용한다.
다른 환경과 실시간 봉의 거래량 집계 기준은 별도로 검증한다.
직전 완성 봉이 부족하거나 평균 거래량이 0이면 진입하지 않는다.
진입당 수량은 고정 5계약이다.
보유 중 같은 방향 신호의 추가 진입을 허용하고 반대 방향 신호는 건너뛴다.
전략 자체의 전체 보유 수량 한도는 두지 않는다.
실제 신규 주문 시 계좌의 주문 가능 수량을 확인한다.
5계약이 주문 가능 수량을 초과하면 가능한 수량만 주문하고 계획 수량과 실제 주문 수량을 각각 기록한다.
동일 고저점에서 한 번만 진입하는 제한은 적용하지 않는다.

장중 진입 주문에는 시장가를 사용한다.
이전 주문이 미체결이거나 처리 상태를 확인하지 못한 동안 발생한 새 장중 진입 신호는 주문하지 않고 이유를 기록한다.
청산 주문을 처리하는 동안에는 주문의 체결·취소 상태와 실제 잔여 수량이 확인될 때까지 신규·추가 진입을 막는다.
그동안 발생한 진입 신호는 건너뛰고 나중에 재주문하지 않는다.
기존 포지션의 손절과 청산 관리는 계속하되 이미 청산 주문이 접수된 수량에 중복 주문하지 않는다.
진입 주문이 신호 발생 후 다음 3분봉이 끝날 때까지 미체결이면 남은 수량을 취소 요청하고 취소·체결 상태를 확인한다.
같은 신호로 재주문하지 않는다.
진입 주문이 명확히 거부되면 사유와 수량을 기록하고 해당 신호로 재주문하지 않는다.
접수 여부가 불명확하면 거부로 단정하지 않고 실제 주문·체결 상태를 확인하기 전까지 새 주문을 멈춘다.
15:24 주문 제한과 15:30 당일 청산이 더 먼저 도래하면 해당 절차를 우선한다.

## 목표와 손절

| 포지션 | 이익 청산 목표 | 손절 기준 |
| --- | --- | --- |
| 매수 | 반대쪽 확정 고점 | 해당 진입의 기준 저점보다 1,500원 아래 |
| 매도 | 반대쪽 확정 저점 | 해당 진입의 기준 고점보다 1,500원 위 |

첫 이익 청산 목표는 진입 후보 봉이 시작되기 전에 확정된 가장 최근 반대쪽 고저점을 사용한다.
목표 갱신 방식을 기본으로 하며 보유 중 새로운 반대쪽 고점 또는 저점이 확정되면 각 진입분의 이익 청산 목표를 새 기준으로 갱신한다.
목표를 갱신해도 각 진입분의 손절 기준은 바꾸지 않는다.
진입분별 실제 체결 수량, 남은 수량, 손절 기준과 현재 목표를 기록해 재시작 후에도 대조한다.
목표 갱신을 확인한 시점에 현재 가격이 새 목표에 도달했거나 이를 지났으면 해당 보유분을 즉시 청산 시도한다.
새 목표가 진입 가격보다 불리하면 목표 청산도 손실로 끝날 수 있다.

### 목표 고정 대안

목표 고정 방식은 구현상 어려움이 있거나 구현 단순화가 필요할 때 사용할 수 있는 대안이다.
이 방식을 사용하면 각 진입분의 첫 이익 청산 목표를 보유 중 갱신하지 않는다.
목표 고정을 선택해도 각 진입분의 손절 기준, 장중 청산과 주문 상태 확인 규칙은 유지한다.
사용하는 목표 관리 방식을 실행 전에 정하고 실행 기록과 구현 결과에 명시한다.
보유 중 목표 관리 방식을 변경할 경우 기존 포지션과 주문의 목표를 임의로 바꾸지 않고 상태를 확인한 뒤 처리한다.

## 청산과 주문 상태

목표 또는 손절 가격 도달은 장중 가격으로 확인하고 도달 시 시장가 청산 주문을 시도한다.
같은 진입분에서 현재 가격이 목표와 손절 조건을 동시에 만족하면 청산 이유를 손절로 기록한다.
동시 충족을 이유로 같은 수량에 청산 주문을 중복해서 내지 않는다.
여러 진입분이 청산 대상이면 각 진입분의 대상 수량을 구분하고 실제 잔여 수량과 기존 주문을 확인한다.
거래량 진입 조건은 기존 포지션의 손절과 이익 청산을 막지 않는다.
청산 주문 상태와 실제 보유 수량을 확인하며 잔여 수량 청산을 계속 시도한다.
미체결 주문을 취소해야 할 때는 취소 완료와 체결 여부를 확인한 뒤 남은 수량만 다시 주문한다.
주문 또는 취소 결과가 불명확하면 중복 청산을 막기 위해 추가 자동 주문을 멈추고 상태 조회를 계속한다.
시장가 주문도 원하는 가격이나 전량 체결을 보장하지 않는다.

## 거래 종료와 공통 처리

일반 거래일에는 15:24부터 신규·추가 진입을 제한한다.
15:24에 장중 미체결 주문을 모두 취소 요청하고 취소·체결 상태와 실제 보유 수량을 확인한다.
취소한 주문이 기존 포지션을 청산하기 위한 것이었다면 이미 체결된 수량을 제외하고 남은 청산 대상의 처리를 이어간다.
15:30에는 미체결 주문을 다시 확인·취소 요청하고 취소 결과와 실제 보유 수량을 확인한 뒤 잔여 포지션의 시장가 청산을 시작한다.
청산이 남으면 5초 간격으로 주문 상태와 실제 잔여 수량을 확인한다.
미체결 주문을 취소해야 하는 경우 취소 완료를 확인한 뒤 거래 가능한 시간 안에 남은 수량의 청산을 반복 시도한다.
5초는 상태 확인 간격이며 5초마다 무조건 주문한다는 뜻은 아니다.
주문·취소 상태를 확인할 수 없으면 추가 자동 주문을 멈추고 오류와 마지막 확인 상태를 기록하며 5초 간격으로 조회를 다시 시도한다.
상태가 확인되면 기존 주문·취소 상태와 실제 잔여 수량을 확인해 청산을 이어간다.
전체 API 요청은 종류별 호출 제한을 지키도록 관리한다.
일반 거래일 종가 단일가 시간의 주문·취소·체결 지원과 재시도 마감 시각은 모의환경에서 확인한 뒤 정한다.
최종거래일 등 거래시간이 다른 날은 별도로 처리해야 한다.

해당 월물의 최종거래일에는 신규·추가 진입하지 않는다.
최종거래일을 확인하면 미체결 주문과 실제 보유 수량을 확인하고 거래 가능한 동안 잔여 포지션의 청산을 즉시 시도한다.
미체결 주문이 있으면 취소·체결 상태를 확인해 중복 주문을 막는다.
최종거래일을 확인하지 못하면 신규·추가 진입을 막고 오류를 기록하며 날짜와 기존 포지션·미체결 상태를 계속 조회한다.
주문 가능 수량 API와 실제 주문·취소·부분 체결 및 최종거래일 청산 흐름은 모의환경에서 검증한다.

## 실행 기록

날짜별 파일 하나에 신호, 신호를 건너뛴 이유, 주문 요청과 결과, 실제 체결, 잔여 포지션 및 오류를 시간순으로 기록한다.
전략 손익은 실제 체결 가격과 수량으로 계산한다.
API의 계좌 확정손익 및 수수료와 비교하고 차이가 있으면 확인해 남긴다.
계좌 손익과 수수료에 다른 거래가 포함될 수 있으므로 전략별 구분 가능 여부를 검증한다.
모의계좌 체결과 프로그램 내부 시뮬레이션을 구분한다.
파일의 구체적인 형식과 항목은 구현하면서 정한다.
API 인증정보는 문서와 실행 로그에 기록하지 않는다.

## 백테스트 결과 처리

이 절은 백테스트 기능을 구현하거나 과거 자료로 성과를 계산할 때만 사용한다.
실시간·모의 매매의 주문 조건이나 청산 처리 규칙으로 사용하지 않는다.
백테스트 구현을 별도로 요청받지 않았다면 이 절만을 근거로 백테스트 기능을 추가하지 않는다.

봉의 고가와 저가가 같은 봉에서 목표와 손절에 모두 닿아도 실제 발생 순서는 확인할 수 없다.
봉 내부 순서를 알 수 없는 백테스트에서는 손절을 우선하는 보수적인 가정을 사용하고 그 가정을 결과에 표시한다.
이는 실시간 현재 가격에서 두 조건이 동시에 성립하는 경우와 구분한다.
15:30 청산 가격이 없거나 다른 이유로 포지션을 청산하지 못하면 해당 날짜를 미청산으로 표시하고 실제 남은 가상 포지션과 원인을 기록한다.
미청산이나 분석 불가 날짜가 있으면 전체 기간의 손익과 수익률을 확정 결과로 표시하지 않는다.
확정된 부분의 손익을 별도로 표시할 때도 제외된 날짜와 미청산 수량을 함께 명시한다.
미실현 손익을 빠뜨린 수치를 전체 기간의 완결된 수익률로 제시하지 않는다.

## 자료 공백과 추가 확인

운용 규모와 손실 허용 범위에 비춰 진입당 5계약의 적정성을 추가 검토한다.
실시간 청산 주문의 세부 처리 순서는 구현 전에 명확히 한다.

과거 가정상 결과는 실제 체결이나 향후 수익성을 보장하지 않는다.
