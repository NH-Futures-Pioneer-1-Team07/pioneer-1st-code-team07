# 검증 보고서 작성·갱신

쌓인 조합 결과를 근거로 추천 조합과 그 이유를 `backend/reports/<전략 id>/<보고서 이름>/report.md`에 정리한다. 형식과 판단 기준은 `backend/reports/README.md`를 따른다. 조합 실행은 `sweep-run` 스킬이 맡는다.

## 원칙

- **수치는 파일에서 가져온다.** 본문의 모든 수치는 `table.csv`, `results.jsonl`, 거래 파일의 값이다. 암산하거나 기억에 의존하지 않는다.
- 표에 없는 통계가 필요하면 결과 파일을 읽는 코드를 짜서 계산하고, 무엇을 어떻게 계산했는지 본문에 쓴다.
- **최고점을 고르지 않는다.** 기간별 일관성과 이웃 조합 안정성이 있는 조합을 추천한다.
- 시도 횟수(`results.jsonl` 줄 수)를 항상 적고, 많을수록 우연이 섞인다는 점을 한계에 쓴다.
- 데이터가 모자라 결론을 못 내리면 "낮은 신뢰"로 쓰고 무엇이 더 필요한지 적는다.

## 절차

모든 명령은 `backend/`에서 실행한다.

1. **보고서를 정한다.**
   - 답하려는 질문 한 문장을 정하고, 짧은 보고서 이름을 붙인다.
   - `backend/reports/<전략 id>/`에 같은 질문의 보고서가 있으면 새로 만들지 않고 그 `report.md`를 읽어 갱신한다.
2. **비교표를 만든다.**
   - `uv run python -m app.sweep table <전략 id> --name <보고서 이름>`
   - 만들어진 `table.csv`를 읽는다. 조합이 행이고 기간마다 `지표[시작일~종료일]` 열이 있다.
3. **분석한다.** `backend/reports/README.md`의 판단 기준 순서로 본다.
   - 기간별 일관성: 구간마다 순손익 부호가 같은가, 한 구간이 이익을 독식하는가
   - 이웃 조합 안정성: 값을 한 칸 바꾼 조합의 성과가 비슷한가
   - 비용 영향: `fee_ratio`, 총손익과 순손익 차이
   - 위험: `max_drawdown_rate`, `sharpe`
   - 표본: `trade_count`
   - 필요하면 거래 파일(`sweeps/<전략 id>/trades/<id>.jsonl`)에서 청산 이유별 건수·손익을 계산한다.
4. **보고서를 쓴다.**
   - 머리말(JSON)과 고정 섹션을 `backend/reports/README.md` 형식대로 채운다.
   - `recommended`의 `ids`는 모두 `results.jsonl`에 있는 `id`여야 한다. 조합 하나는 기간마다 `id`가 따로 있다.
   - `## 다음 탐색 제안`에 이유와 `sweep-request` 블록을 쓴다. 이미 해 본 조합은 넣지 않는다.
5. **갱신이면** 달라진 결론을 `## 요약`·`## 추천 조합`·`## 근거`에 반영하고 `## 변경 이력`에 한 줄을 더한다. `updated`와 `result_count`를 고친다.
6. **검증한다.**
   - 본문에 쓴 수치를 `table.csv` 값과 대조한다.
   - 머리말 `recommended`의 `ids`가 모두 `results.jsonl`에 있는지 확인한다.
7. **보고한다.** 추천 조합, 신뢰 수준, 다음 탐색 제안을 짧게 알린다.

## 하지 않는 일

- `results.jsonl`, 거래 파일, 전략 코드, `manifest.json`을 수정하지 않는다.
- 근거 없이 "안정적"이라고 쓰지 않는다. 안정적이라면 어떤 기간·이웃 조합을 비교했는지 쓴다.
- 과거 결과로 미래 수익을 약속하는 표현을 쓰지 않는다.
- 투자 자문처럼 쓰지 않는다. 이 보고서는 모의 백테스트의 비교 결과다.
- 키·토큰·계좌 정보를 보고서에 쓰지 않는다.
